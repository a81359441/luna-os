# 知識をどこに貯めるか

規模が大きくなると必ず出てくる問いです。「これはこのリポジトリに入れるべきか、別の場所か」。

## 原則

**このリポジトリは、恒久的・戦略的・横断的な知識の唯一のマスターです。** プライベートな別リポジトリを使うのは、境界のルールがそれを要求するときだけ（機微な商用データ、取引先固有の実行詳細、重いコードベース）。

戦略を1箇所に集める理由は、**掛け合わせ**です。発信で学んだことがブランドの声を作り、財務のモデルが事業判断を変え、生活のリズムが制作のペースを決める。分散させると、この掛け合わせが起きません。

## 種類別の置き場

| 仕事の種類 | 主な置き場 | 別リポジトリ？ | 例 |
|---|---|---|---|
| 個人の生活・予定・方向性 | `personal-*` ドメイン | ほぼ不要 | 日々の運用、方針、旅程 |
| 発信・SNS・パーソナルブランド | `content-*` ドメイン | 素材が膨大なときだけ | 企画の型、フックの引き出し、分析の学び |
| 事業の高次の話（identity, 物語） | 事業ドメイン | 不要 | ブランドの柱、長期の観客づくり |
| 財務・投資 | `finance` ドメイン（モデルと前提） | **口座・台帳・税務は別** | キャッシュフローの型、投資の論拠 |
| 商用プロダクトの実行 | ポインタのドメインだけ | **必要** | 仕入先、価格、コード、取引条件 |
| 顧客・クライアント案件 | 案件ドメイン（非機微の要約） | 契約・個人情報は別 | 進行中の案件、単価の方針 |

## 判断の順番

1. **1年後もまだ正しく、役に立つか？** ノーなら、そもそも統合層に入れない（揮発する場所に置いて索引から案内する）。
2. **他人の機微な情報が入っているか？** イエスなら、別のプライベートリポジトリ。ここにはポインタだけ。
3. **将来の判断に効くか？** イエスなら、ここに置く。

## ポインタのドメインの書き方

機微な中身を外に置くとき、こちらには次のようなドメインを1つ作ります。

```markdown
# <プロジェクト名>｜ドメイン索引

**状態**: 稼働中（ポインタ）
**実体の置き場**: プライベートリポジトリ `<repo>`（別途）

このドメインは**案内板**です。実行の詳細（取引先、価格、契約）はここに書きません。

## ここに書いてよいこと
- 高次の方針と、ここでの判断に必要な非機微の事実
- 相手先リポジトリのどこを見ればよいかの案内

## ここに書いてはいけないこと
- 実際の金額、個人名、契約条件、認証情報
```

こうすると、マスターは全体像を保ったまま、機微な情報を持ち歩かずに済みます。
