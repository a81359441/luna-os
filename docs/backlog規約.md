# Backlog 規約

backlog がどこに住み、何を持ち、**いつ読まれるか**の正本。

## なぜ必要か

セッション中に浮かんだアイデアには行き場が要る。無いと**その場で着手する**（本来の作業が脱線する）か**消える**の二択になる。

そして置き場を作るだけでは足りない。**読まれる仕組みの無い backlog は墓場になる。** だからこの規約は書式より先に「いつ読まれるか」を定める。

> この雛形の元になったリポジトリでの実測: 出力先が無かったスキルの記録ファイルは、106日間で1件しか増えなかった。原因は「引かれる場所が無いものは引かれない」。

## 層

backlog は **Connections**（`CLAUDE.md` の取り込み前ゲートで「未処理のToDo」は名指しされている）。

> **`index.md` に取り込まない。** 索引は backlog へ**案内するだけ**。
> 取り込むと統合層が週単位で腐るデータを抱え込む。

## どこに住むか

| 置き場 | 持つもの |
|---|---|
| `knowledge/domains/<domain>/backlog.md` | そのドメインの中で完結する仕事 |
| `tasks/backlog.md` | **本当に**複数ドメインにまたがる仕事、またはドメインを持たないシステム全体の仕事 |

**分割ルール:** 「これは1つのドメインの中で終わるか」を訊く。終わるなら**ドメイン側**。迷ったらドメイン側。`tasks/backlog.md` は最後の手段であって既定値ではない。

> 同じリポジトリでの実測: `tasks/backlog.md` の21行のうち**19行がドメイン固有**だった。ドメインに置き場が無かったので全部そこへ流れていた。既定値を間違えると system backlog は必ず junk drawer になる。

## 書式

```markdown
# <ドメイン名> Backlog

Connections 層。index.md には取り込まない。
セッション中に浮かんだものはここに置き、そのセッションでは着手しない。

**記法:** `[ ]` 未着手 · `[~]` 進行中 · `[x]` 完了 · `⚠要判断` · `💤` 保留 · `🔒` この端末だけ
各節で新しいものが上。

## ⏰ 期限あり
- [ ] **見出しは太字で1行** ⏰2026-09-30
      補足はインデントして下に。行を長くしない。

## 未着手
- [~] **返信を送る** ✉ to:someone@example.co.jp thread:<ID> since:2026-10-02
      送信待ちの印。`bin/sent-check` が送信済みフォルダと照合する（jp-email が下書き作成時に付ける）。
- [ ] **見出し**
- [~] **進行中のもの** 待ち: 先方の返信
- [ ] **判断が要るもの** ⚠要判断

## 💤 保留（起動条件つき）
- [ ] **意図的に寝かせているもの** 💤 起動条件: <何が起きたら起こすか>

## 完了
- [x] 2026-09-20 やったこと
```

### 節

**必須は3つだけ:** `## ⏰ 期限あり` · `## 💤 保留（起動条件つき）` · `## 完了`。

- **⏰ 期限あり** は本物の期限があるものだけ。「早めに」は期限ではない。ここが膨らむと全部が緊急に見えて機能しなくなる。
- **💤 保留** は**起動条件を書かないと入れられない**。条件の無い保留はただの未着手であり、毎回ノイズになる。
- **完了** は日付つき。消さない。

**その間の節はドメインの都合で分けてよい。** 既定は `## 未着手` 1つ。数が増えたらテーマで割る（生活系なら「移動」「健康」「お金」など）。

### 🔒 この端末から出さない

backlog に書いたものは、`bin/menu --json` を読む surface にもそのまま出る。
端末のブリーフと外に出るブリーフは**同じ計算から描かれる**ので、片方にだけ
載る項目は無い（朝の通知やスマホへの push を足した場合)。

出したくない1行には **`🔒` を項目のどこかに書く**。見出し行でも、下の
インデント行でもよい。

```markdown
- [ ] **金額の交渉**  ⏰2026-10-01 🔒
```

- **端末では今まで通り全文が出る。** 隠すのは端末の外に出る surface だけ。
- **外には件数だけ出る。** 黙って消えるのではなく、隠したことが見える形にする。
- カレンダーの予定名にも同じ 🔒 が効く。
- 見出し行の `★` は「大事」の印。ブリーフの「今日の3つ」と「今週見ておくこと」はここから選ばれる。

**なぜ書く瞬間に付けるのか:** それが唯一「これは人に見せたくない」と分かって
いる瞬間だから。あとから除外リストを保守する方式は、保守されなくなった時に
**黙って漏れる**。🔒 は opt-out なので、付け忘れれば出る。つまりこれは仕組み
ではなく**規律**であり、そこは正直に書いておく。

### 1行の作り方

見出しは**太字で1行**。補足はインデントして下へ。

> テーブル形式にしない理由: 実際に **802文字のセル**を生んだから。チェックボックスは構造的に長い行になりにくく、スマホで横スクロールが出ない。

長い項目を移してくる時は**要約しない**。見出しだけ立てて本文はそのままインデントで下に置く。要約は書き換えであり、未決事項を静かに消す。

## いつ書かれるか（捕捉）

- セッション中に「**todo:**」「**backlog:**」と言われたら、**今いるドメインの backlog に1行足して、作業は始めない**。着手するかどうかは別の判断で、別のセッションでやる。
- `closeout` が、そのセッションで出た未着手項目を該当ドメインの backlog へ流す。

## いつ読まれるか（ここが本体）

1. **ドメインに入った時**、AI が訊かれる前に open 項目を出す。探しに行くのではなく、向こうから出る。
2. 起動メニューを持つ環境では、ドメイン行に open 件数を出す。`backlog.md` があって open がある時だけ。無い時は `0` ではなく**何も出さない**（0 を出すと未導入のドメインで「壊れている」ように見える）。

集計は **`## 💤 保留` と `## 完了` 以外の節にある `[ ]` と `[~]`** を数える。節名で拾うのではなく**除外**で数えるので、テーマ節を自由に足しても集計は壊れない。

## 出ていく時

- 着手したら `[~]`。
- 終わったら `[x]` + 日付。**消さない。**
- ドメインを間違えていたら、正しいドメインの backlog へ移す（要約せずそのまま）。
- 恒久的にやらないと決めたら `[x]` にして「やらないと決めた、理由」を書く。黙って消さない。
