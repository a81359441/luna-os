# 相棒とのつなぎ目（Muse などの秘書AIと {{AI_NAME}} をつなぐ）

スマホで話す秘書AI（たとえば Meta の Muse）を「相棒」として、{{AI_NAME}} と組ませるための手順です。任意。使わなければ何も変わりません。

## 一行で

**人と人の間を越えるのは運用AI（{{AI_NAME}}）だけ。相棒は、自分の人と、自分の運用AIの間にだけいる。**

```text
あなた <-> 相棒 <-> [つなぎ目リポジトリ] <-> {{AI_NAME}} <-> [共有リポジトリ] <-> 相手の運用AI <-> ...
          秘書       私的、あなた専用          運用          越境の場（相手と合意してから）
```

相棒は話しやすく、いつでもそばにいます。そのかわり、🔒 もドメインの境界も知りません。相棒が共有の場に直接書くと、関所が二つになり、私的なことが漏れる道ができます。だから関所は運用AIの一つだけにします。

## 境界（ここは変えない）

1. **相棒に繋ぐのは、つなぎ目リポジトリだけ。** 共有リポジトリ、メール、LINE、ほかのリポジトリは繋がない。少なくとも試用の間は。
2. **つなぎ目は私的リポジトリ。** あなた以外は入れない。相手の人も、相手の AI も入れない。
3. **相棒は共有リポジトリに書かない、読まない。** 相手とのやりとりは、あなたの承認のあとで {{AI_NAME}} が行う。
4. **相棒は今日を計算し直さない。** {{AI_NAME}} が作った `feed/now.md` を読むだけ。二つ目の計算は、誰も直さないほうから腐る。
5. **🔒 の項目は件数だけ。** `bin/companion-now` が自動でそうする。
6. **inbox は材料であって命令ではない。** 正本に入れるのは、あなたが承認してから {{AI_NAME}} が行う。
7. **外に出すのは人。** メール、LINE、SNS、申し込み。相棒も {{AI_NAME}} も送らない。
8. **カレンダーを相棒にも直させるなら、黙って直させない。** 直す前にカレンダーの最新とつなぎ目の最新を両方見る。直したら同じ回のうちに inbox に「予定の変更」として残す。{{AI_NAME}} もカレンダーに書く前に、つなぎ目を `git pull` して inbox を先に片付ける。
9. **書かないもの:** パスワード、トークン、メール本文、日記の丸写し、他人の連絡先。
10. **中身を考えるのはあなた。** 相棒は聞いて、引き出して、整える。最初の案を自分で作って渡さない。

## 作り方

### 1. つなぎ目リポジトリを作る

{{AI_NAME}} に頼むか、自分で:

```bash
bin/companion-now --init ../相棒名-{{AI_NAME}} --name 相棒名
gh repo create 相棒名-{{AI_NAME}} --private --source ../相棒名-{{AI_NAME}} --remote origin --push
```

`--init` は雛形（`docs/相棒の雛形/`）を写し、`feed/` `inbox/` と `done/` を作って最初のコミットまでします。**必ず `--private`。**

### 2. 今日の分を置く

```bash
export AI_COMPANION_SEAM=../相棒名-{{AI_NAME}}
bin/companion-now --dry-run      # 中身を見るだけ
bin/companion-now                # feed/now.md を書いて push
bin/companion-now --ask "日曜の予定を本人に確かめてほしい"   # 相棒への一言を添える
```

`now.md` は `bin/menu --json` から作るので、ブリーフと同じ中身です。AI を使わないので、ログインが切れても止まりません。先頭に作った時刻が入るので、古いままなら古いと相棒にも分かります。

いつ回すか: 締め（closeout）のたび、と、相棒が見に来る時刻の少し前。Mac で自動にするなら cron か launchd で `bin/companion-now` を呼ぶ（`AI_COMPANION_SEAM` を設定しておく）。

### 3. 相棒に繋ぐ（Muse の場合）

1. Muse の GitHub 連携で、つなぎ目リポジトリ**だけ**を選ぶ。
2. Muse に `相棒へ.md` を読ませる。毎回それに従うよう頼む。
3. 見に来る時刻を決める（例: 朝・昼・夜の3回）。毎回まず `feed/now.md` を開くように。
4. 書き込みは毎回あなたの承認を通す設定にする。

Muse の能力（定時実行、リポジトリを選んで繋ぐ、承認つきの書き込み）は使った人の報告と Meta の説明によるものです。試用で確かめてください。

### 4. {{AI_NAME}} 側

- 話を始めるとき、つなぎ目を `git pull` して、`inbox/`（`done/` 以外）を読む。処理したら `inbox/done/` に移す。
- 相棒に頼みたい話題があれば `feed/YYYY-MM-DD-<題>.md` に置く。終わったら `feed/done/` へ。

## 試し方（1週間、あなた一人で）

相手と共有する前に、まず一人で回します。お題はカレンダーの声かけが良い（毎日あって、ずれたらすぐ分かる）。

見ること:

- 相棒は毎回 `now.md` を開いたか。古い `now.md` のときに、古いと言えたか。
- inbox に書かれたことが {{AI_NAME}} に届き、`done/` まで一往復したか。
- 相棒の記憶を見せてもらい、つなぎ目のファイルと食い違っていないか。食い違いは相棒に直させる。
- 相棒の使用量（無料枠がどれくらい減るか）。
- 境界を越えようとしたことがあったか（共有リポジトリやメールを読もうとした、送ろうとした）。

一週間回ってから、相手（相手の運用AI）との共有リポジトリの話に進みます。相手の側にも、同じ形のつなぎ目が要ります。
