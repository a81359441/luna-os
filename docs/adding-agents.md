# エージェントの増やし方

**基本方針：作らないこと。** マスターモードでほとんどの仕事は足ります。エージェントを増やすのは、**実際にボトルネックが起きてから**です。

## 作ってよい条件（4つ全部を満たすとき）

1. 同じ種類の仕事が**繰り返し**発生している。
2. 参照すべきファイル群が**毎回同じ**。
3. **やってはいけないこと**が明確にある（規約、境界、主張の制限）。
4. 毎回同じ説明をしているのが煩わしい。

1つでも欠けるなら、まだスキルかドメインで足ります。

## 作り方

1. `.claude/agents/<slug>.md` を作る。

```markdown
---
name: <slug>
description: <一行の役割。起動語も書く。「<word>」と言われたら起動>
tools: Read, Grep, Glob
---

# <役割名>

<この役割が何をするか3〜5行>

## 参照するファイル

- `knowledge/domains/<domain>/index.md`
- <ほか>

## 使うとき

<条件>

## してはいけないこと

- <特に、根拠なく主張してはいけないことの種類>
- 承認なしに真実のファイルを書き換えない
- 公開・送信・投稿はしない（人間が実行する）

## エスカレーション先

マスター（横断の判断、境界の曖昧さ、システムの変更）
```

2. `agents/registry.md` に1ブロック追加する（雛形はそのファイルの末尾にあります）。

## 権限の設計

読み取り専用（`Read, Grep, Glob`）から始めてください。書き込みが本当に必要になってから広げます。エージェントが書けないことは、事故が起きないことです。

## よくある失敗

- **エージェントごっこ**：実際には1つの仕事なのに、複数が働いているように見せる。信頼を失います。
- **逐次的な多段をエージェントの連鎖で回す**：受け渡しが雑になり、トークンも食う。フェーズに分けて**ファイル**で引き継ぐこと。
- **範囲が曖昧なまま作る**：スコープ・参照・成果物・エスカレーション先を言えないなら、まだ作る段階ではありません。

## 向いている使い方

サブエージェントが本当に効くのは**並列のリサーチと文脈の抽出**です。長い資料を読む、多数のファイルを走査する、独立した角度から情報を集める。それぞれが**要約して**返せば、マスター側の文脈は軽いままです。
