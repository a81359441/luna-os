# 個人AIオペレーティングシステム（テンプレート）

**人生・事業・プロジェクトを横断して、AIが「嘘をつかない相棒」として育っていくための、軽くて持ち運べる土台。**

これはアプリケーションではありません。中身はただのMarkdownファイルの集まりです。Claude Code で開くと `CLAUDE.md` が自動で読み込まれ、AIがこのシステムの規律に従って動き出します。ファイルが素のMarkdownなので、将来ほかのAIに移ることもできます。

このテンプレートは、実際に1年以上運用されている個人AI OSから、個人データを取り除いて汎用化したものです。**構造と規律だけが入っていて、中身は空**です。あなたの知識をこれから入れていきます。

## 何が普通のチャットと違うのか

普通のチャットは、会話が終われば忘れます。思い出したように過去の話を持ち出しても、それが本当にあったことか、AIがその場で作った話か、区別がつきません。

このシステムは**ファイルを唯一の真実**として扱います。

- AIはナレッジベースにある事実しか断定しない。無ければ「情報がありません」と言う。
- 新しい知識は必ず**ブランチ上の提案**として出てくる。あなたが承認（マージ）してはじめて真実になる。
- 会話は使い捨て。残すべきものは必ずファイルになる。
- 個人・商用・発信の境界は、書き込む前に必ず宣言・確認される。

結果として、半年後にこのシステムに聞いたことの答えが、**半年前のあなたが承認した内容と一致します**。これが「賢そうに見えること」より大事にしている一点です。

## 構造

| 層 | ファイル | 役割 |
|---|---|---|
| **ルール** | `CLAUDE.md`, `.claude/**` | AIの動き方。滅多に変えない。 |
| **現在** | `state.md` | 今の優先事項と稼働中ドメイン。小さく最新。ブリーフの順位は backlog の `★` から計算する。 |
| **統合** | `knowledge/index.md`, 各ドメインの `index.md` | 「今なにが真実か」。追記ではなく更新する。 |
| **履歴** | `intentions-log.md`, `tasks/sessions.md` | 何が起きたかの追記専用ログ。 |
| **キュー** | `tasks/backlog.md`, 各ドメインの `backlog.md` | まだ終わっていない仕事。索引には取り込まない。 |
| **一次情報** | `diary/entries/`, `research/notes/` | 生の体験・学習素材。書いたら不変。 |

├── state.md                   # Tier-0要約：今の優先事項
├── knowledge/
│   ├── index.md               # ドメインの全体台帳
│   └── domains/
│       └── _template/         # 新ドメインの雛形（コピー元）
├── agents/                    # 役割の定義と仕事の流れ
├── tasks/                     # 横断バックログと自己診断ログ

├── bin/
│   ├── start                  # どこからでもセッションを開くランチャー
│   ├── menu                   # スタートメニュー＝ブリーフ（次の一手・今日・締切）

## 5分で始める

ターミナルやgitを使ったことがなければ、先に画面つきのガイド **https://luna-os.surge.sh** へ（パソコンに詳しくない方向け。アプリのダウンロードから一歩ずつ案内します。同じ内容が `INSTALL.md` にもあります）。

1. このフォルダで `claude "setup"` と打つ。AIの名前とあなたの呼び方を決め、名前で呼び出せるようにし、最初のドメインを作ります。
2. あとは普通に話しかける。**仕事が一段落したら `closeout`（締めて）。** 締めの動詞はこれ1つだけです。
3. ブリーフの「はじめの一歩」に、Gmail とカレンダーをつなぐ手順などが出ます。「チュートリアル」と言えば1つずつ一緒にやります。

ガイドのサイトは `site/` にあります。テンプレートとして使うだけなら、`site/` は消してかまいません。

詳しい手順は **`SETUP.md`** にあります。

## 外部データを読ませる

前の AI（ブラウザの Claude や ChatGPT）からの引っ越しは `docs/moving-in.md`。過去の会話をそのまま移さず、まず分析してドメインの形を一緒に決め、OK したものだけを保存します。

`bin/gmail/` を使うと、自分のGmailをAIに読ませて整理させられます（**読み取り専用**。送信・下書き・削除のコードは1行も入っていません）。設定は `bin/gmail/README.md` に15分の手順があります。

`bin/gcal/` は Google カレンダーの中に**AI専用のレイヤを1枚**作ります。スマホでは独立したカレンダーとして出るので、手で管理しているものとは混ざりません。トークンの権限設計上、**自分で作った予定に手が届かない段階**も選べます（`bin/gcal/README.md`）。ここでも原則は同じで、**推測した日付は絶対に予約しません**。

原則はここでも同じです。**生のメールは索引に入れません。** 取り出したメールは `data/`（gitignore対象）に置き、そこからコンパイルされた個人情報を含まない事実だけが `knowledge/` に残ります。

## 中心にある考え方

- **ドメイン**＝知識の境界。仕事、健康、発信、事業、それぞれが独立した索引を持つ。
- **統合（index.md）**＝「今の真実」。ここを更新することで知識が複利で積み上がる。ログを増やすだけでは賢くならない。
- **Context と Connections**：1年後も正しいものだけを索引に入れる。今週で入れ替わるものは、揮発する場所に置いたまま索引から案内する。
- **承認してはじめて真実**：あなたが真実の管理者であり続ける。

## セッションを開くと最初に出るもの

目次ではなく**ブリーフ**です。「今日の3つ」（`★` の付いた backlog 項目から順位つきで3つ。カレンダーの予定は別の「予定」に出ます）、今週見ておくこと、この先の予定。**ドメインの一覧はわざと出していません**（`d` のキー1つ先）。行き先が20個並ぶメニューは、そのセッションが開かれた理由を見失わせるからです。

`d` ドメイン · `b` backlog · `h` 履歴 · `m` 地図 · `skill` スキル一覧 · `resume` 途中保存

## よく使う動詞

| 言葉 | 起きること |
|---|---|
| `setup` | 初回セットアップ |
| `add-domain` | 新しい知識領域を作って台帳に登録 |
| `grill` | 頭の中にあることを質問攻めで引き出し、統合に落とす |
| `log` | 体験を日記として残す（一次情報） |
| `distill` | 見た動画・読んだ記事を蒸留してリサーチに残す |
| `closeout` | **締めの唯一の動詞**。完了なら片付け → 統合 → ログ → ブランチ着地 → 掃除。途中なら保存して `/clear` のあと続きから |
| `history` | 過去のセッションを探して開き直す |
| `self-diagnose` | システム自体の健康診断と週次の振り返り |

日本語でも呼べます（「締め」「深掘り」「抽出」「履歴」…）。一覧は `skill` と打つか `bin/skills`。

## 育て方

最初は空で構いません。むしろ空から始めるのが正しい使い方です。

1. **ドメインを1つだけ作る**（`add-domain`）。全部作ろうとしない。
2. そのドメインについて **`grill`** で30分喋る。AIが質問し、あなたが答え、統合に落ちる。
3. 仕事が動いたら **`closeout`**。索引が更新され、ログが積まれる。
4. これを数週間繰り返すと、AIがあなたの文脈を「思い出す」のではなく「参照する」ようになります。

ドメインを増やすのは、同じ種類の仕事が繰り返し発生してからで十分です。`docs/adding-domains.md` を参照。
