# 自己診断

**数えるのはコードの仕事です。** `bin/lint` が git の衛生、鮮度、ドメインの登録、ウィキリンク、ダッシュ、backlog の健康、索引の重さ、メモリの置き場所、スキルの使用状況を、毎回、無料で数えます。どれかが閾値を越えると、ブリーフの「忘れずに」に「点検:」の一行が出ます。このスキルは残りの半分、**スクリプトにはできない判断**だけを持ちます。

以前は5つの点検を全部手で回していましたが、手で回す点検はそのうち回らなくなり、回っても本当に起きていることを見落とします。だから短くしてあります。健全なら「健全です」と一行で言って終わる。

## 手順0: 数字を読む

```bash
bin/lint
```

出力について**考える**こと。手で数え直さないこと。前回までに片付いたことを蒸し返さないよう、`tasks/self-diagnosis-log.md` にもざっと目を通す。

## 6つの判断

lint の出力かこのセッションが「見る理由」をくれたものだけを選ぶ。多くのファイルを読む判断は読み取り用のサブエージェントに任せ、結論だけ受け取る。

1. **自分と矛盾する真実。** クイックリファレンスの行、`state.md` の一行、`index.md` の主張のうち、そのドメイン自身のファイルがもう否定しているもの（直した不具合がまだ未解決として載っている、動いた数字、変わった名前）。両方の `file:line` を示す。
2. **現実と合わなくなった backlog。** 仕事はもう git や索引の中で終わっているのに開いたままの項目（それが指すものについて `git log --oneline -- <パス>` を見る）、黙って過ぎた `⏰` の日付、30日を越えて待っている `⚠要判断`（lint が一覧にする）。直したのに開いたままの項目は、そのうち誰かが二度調べることになります。
3. **境界の逸れ。** `#個人` `#商用` `#発信` の素材が、違うドメインや違うリポジトリに入り込んでいないか。他人の素材が自分のリポジトリに紛れていないか。宣言、タグ、確認。頼まれずに動かさない。
4. **置き場所を間違えたメモリ。** Claude Code の自動メモリは**好み**だけの場所です。前回から増えたメモリを置き場所のテストで振り分ける: **ドメインの事実**はそのドメインのファイルへ、**どのハーネスでも守るべきルール**は `CLAUDE.md` かスキルへ、**好み**だけが残る。古くなったメモリ（その後に変わった仕組みを説明している）や、ファイルにすでにあるルールの重複も指摘する。重複は必ずずれます。機械的な兆候（事実の種類のメモリ、`MEMORY.md` の切れたリンク、symlink）は lint が出す。振り分けはあなたの仕事です。メモリにしか無いルールは、Codex や Grok からは見えません。
5. **誰も呼ばないスキル。** lint は、この端末の会話履歴で一度も呼ばれていないスキルを出します。1つずつ判断する: **畳む**（必要が消えた）、**統合する**（別の動詞がやっている）、**起動語を見直す**（必要は本物なのに、何もそれを表に出していない。これはスキルではなくブリーフかフックの問題）。呼び出しなしで手順だけ追われたスキルは履歴に残らないので、この一覧は手がかりであって判決ではありません。
6. **実際の仕事と合わなくなった優先度。**（以前の `weekly-review` の役目。どちらの儀式も習慣にならなかったので統合した）`state.md` の活動中のドメインと `## Now` を、仕事が実際に向かった先（lint のドメインごとの鮮度、`tasks/sessions.md` の直近2週間）と比べる。優先と書かれているのに30日動いていないドメイン、仕事の大半を担っているのに載っていないドメインは指摘に当たる。`state.md` の差分を提案する。頼まれずに書き換えない。

## 出力

```markdown
# 自己診断 <YYYY-MM-DD>

**判定**: <健全 / 逸れつつある / 要対応>、そして一番大きなリスク。

## 見つかったこと
1. <大事なものから。それぞれ file:line と修正案を1つ>

## 修正案
- <小さいものから。「安全」か「あなたの判断が要る」かを付ける>
```

大事なことだけ。5件は多い。1件でもいい。

## 走らせたあと

- **`tasks/self-diagnosis-log.md` の先頭に1エントリ書く。** 日付、判定、上位1〜3項目。
- **今直さないものは駐める。** 1件1行で、持ち主のドメインの `backlog.md` へ。
- **修正は承認されてから。** 短いブランチに載せ、`closeout` で着地させる。無関係なファイルを巻き込まない。
- **一押しを取り直す。** 直したら `bin/menu --refresh` で、解決済みの問題をブリーフが出し続けないようにする。
- **頻度は実績で決める。** 二度役に立ったら、どの間隔で回すか（毎週、隔週、毎月）を決める。モデルを毎晩走らせる定期実行にはしないこと。毎晩の分は `bin/lint` がやっていて、それはタダです。
- **自動で回すなら、報告だけにする。** 無人の実行は読むことと lint だけを許し、編集・コミットはさせない。修正と記録は、人がいるセッションでやる。作業中の未コミットの変更を指摘しないよう、`origin/main` を切り出した別の作業ツリーで走らせる。失敗した回と走らなかった週は、静かな週と見分けがつくようにブリーフへ出す。
