# 再開の確認手順

本物のセッションの状態ではなく、一時的なリポジトリと、ローカルの bare リモートで試す。`session-resume.sh` は本物を使い、`CLAUDE_PROJECT_DIR` を一時的なチェックアウトに向ける。

1. **保存して、まっさらから再開できる**：途中の仕事と、`branch:`・`next:`・決まったこと入りの `[~]` の backlog 項目を書き、両方を commit し、トピックのブランチを push し、HEAD と `git ls-remote` を比べる。そのブランチを `.session/` の無い新しい場所に clone する。途中の仕事と引き継ぎの全部が取り戻せること。
2. **push に失敗する**：届かないリモートを使い、commit した仕事はローカルに残す。push もリモートの確認も失敗し、新しい再開ポインタも「clear してよい」も出ないこと。リモートを戻し、push して確認してから先へ。
3. **ポインタの前で中断する**：確認済みの push のあと、ポインタを書かない。保存したブランチを新しく clone して backlog を読む。次の一手と決まったことが、そこに残っていること。既定のブランチにこの途中の仕事が入っている必要はない。
4. **一度だけ届く**：確認済みの引き継ぎを一時的なチェックアウトの `.session/resume-pending` に書く。フックを走らせると引き継ぎを出してポインタを消すこと。2回目は何も出さず、git の backlog は変わらないこと。

手順そのものも見直す：commit より先に backlog、ポインタや成功の宣言より先にリモートの確認、`.session/` にしか無い引き継ぎ情報を作らないこと。
