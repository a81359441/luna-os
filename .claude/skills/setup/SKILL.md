# セットアップ（初回だけ）

このリポジトリはテンプレートとして配られています。中身は空です。相手は、ほぼ間違いなく**ターミナルを今日はじめて触った人**です。

ゴールは1つ。**終わったとき、AIが相手について本当のことを1つ知っている**こと。全部を設定し終えることではありません。カレンダーやメールは、あとで「はじめの一歩」として案内します（`tasks/onboarding.md`、`tutorial` スキル）。

## 話し方

- 日本語。短く、やさしく、1回に1つだけ聞く。
- 専門用語を使わない。「リポジトリ」「コミット」「シンボリックリンク」は言わない。「保存」「呼び出せるようにする」と言う。
- 英語の確認（`Do you want to proceed?` など）が出そうな操作は、**相手が同意したあと、実行する直前に**1行で予告する：「このあと英語で確認が出たら `Yes` を選んでください」。質問と予告を同じ発言に入れない（相手はその場で確認が出ると思って待ってしまう）。手順3で権限を整えたあとは、ほぼ出ない。

## 手順

### 1. 状態を確認する（黙って）

Bash ではなく Grep ツールで探す（Bash だと、最初の一手で英語の確認が出る）。中身はこれと同じ：

```bash
grep -rl '{{AI_NAME}}' . --exclude-dir=.git | grep -v -e 'skills/setup/SKILL.md' -e '^./bin/init$'
```

ヒットが無ければセットアップ済み。「もう準備はできています」と1行で伝え、`tutorial` を提案して終わる。

### 2. あいさつして、2つだけ聞く（順に）

最初の発言はこれだけ：

> 「はじめまして。あなた専用のAIです。最初に2つだけ決めさせてください。まず、わたしの名前は何にしますか？（例：ルナ、ハル、相棒）」

| 聞くこと | 使い道 |
|---|---|
| **わたしの名前** | 全ファイルの名前、呼び出しコマンド |
| **あなたの呼び方** | 呼びかけと `state.md` |

名前は後から変えられる、と添えて悩ませない。言語は日本語のまま。アイコンは聞かない（既定のまま。変えたければ後で）。

**名前は相手が書いた表記のまま使う。** `pikachu` と書かれたら `pikachu`。勝手にカタカナや漢字に直さない。

### 3. 確認の手間を減らす（同意をもらってから）

このままだと、わたしがファイルを保存したり記録を残したりするたびに、英語で「実行してよいか」が出ます。最初に一度だけ、まとめて任せてもらう：

> 「このあと、わたしがファイルの保存や記録をするたびに英語の確認が出ます。このフォルダの中の、ふだんの作業だけは聞かずに進めてもいいですか？ 消すような危ない操作は、これまでどおり止まります。」

はいなら `bin/permissions --apply`（`.claude/permissions-preset.json` を、この Mac だけの設定に足す）。中身を知りたいと言われたら `bin/permissions` の出力を見せる。いいえなら、そのまま進む（確認のたびに `Yes` を選んでもらう）。

**効くのは次の起動から。** このセッションの残りでは確認が出ることがある、と1行添える。

### 4. 呼び出しコマンド名を決めて、`bin/init` を実行する

コマンド名は、名前の英小文字ローマ字（ルナ→`luna`、相棒→`aibou`、ハル→`haru`）。英数字の名前ならそのまま小文字に。1つ提案して、よければ実行：

> 「次からは iTerm で `luna` と打てば、わたしが開くようにします。」

```bash
bin/init <名前> <コマンド名>
```

`bin/init` がやること：名前の置き換え、`~/.local/bin/<コマンド名>` の作成（必要なら `~/.zshrc` に PATH を足す）、git の名前とメールが空なら GitHub のアカウントから設定。

- `TAKEN:` で止まったら、そのコマンド名は Mac で既に使われている。別案を1つ出して（`luna2`、`myluna` など）、もう一度。
- `git: 名前とメールが未設定` と出たら、`gh auth login` がまだ。手順を案内してから続ける。

### 5. `state.md` を埋める（黙って）

- 最終更新に今日の日付。
- `**ユーザーの呼び方**:` の行に、聞いた呼び方。
- 優先事項は「最初のドメインを育てる」だけでよい。

### 6. 最初のドメインを1つだけ作る

> 「最後に1つ。いま、いちばん頭を使っていることは何ですか？仕事、家のこと、趣味、なんでも。」

返ってきたものを1つのドメインにする。「仕事」のように広すぎる答えなら、1つだけ聞き足す：「どんなお仕事ですか？一言で大丈夫です。」

`bin/new-domain <slug> <表示名> "<一行の目的>"` で作る（雛形の複製と、索引・state・表示名への登録を1回で。slug は英小文字の短い名前）。ほかは `add-domain` スキルの手順に従う。ただし初回なので、ブランチは切らずにそのまま保存してよい。README の知識ポリシーは、相手に専門用語で聞かず、会話から推して埋める。推しただけなので、ポリシーの頭に「（セットアップ時の仮置き。深掘りで確かめて直す）」と書く（`add-domain` の「発明しない」は、この印で守る）。**1つだけ**。

仕事のように**人の名前や社外秘が混ざりやすい分野**なら、作ったあとに1行だけ添える：「お客さんの名前や社内の秘密は、ここには書かない決まりにしておきました。」

### 7. 保存する（黙って）

```bash
git add -u && git add knowledge/domains/<slug> && git commit -m "setup: <名前> として初期化、最初のドメイン <slug> を作成"
```

（`-A` は使わない。フックが止める。`-u` で `bin/init` が書き換えた分を、新しいドメインはパスで足す。push はしない。`closeout` がやる）

### 8. そのまま深掘りへ

準備完了を1行で伝え、そのまま `grill` を始めてよいか聞く：

> 「準備ができました。このまま少しだけ、<ドメイン> について質問させてください。答えた分だけ、次からのわたしが賢くなります。（やめたいときは『また今度』で大丈夫です）」

はいなら `grill` スキルへ。今日はここまでなら、1行（「次からは iTerm で `<コマンド名>` と打てば会えます。」）のあと、**次に開いたときのメインメニュー**を見せて締める：`bin/menu --no-color` の出力をそのままコードブロックで。「はじめの一歩」が次にやることを案内しているので、説明は足さない。

`grill` を最後までやったら、`tasks/onboarding.md` の「最初のドメインを深掘りする」に印（`- [x]`）を付けて保存する。

## やらないこと

- ドメインを2つ以上作らない。空のフォルダが増えるだけ。
- カレンダー、メール、ステータスバーの設定をここでしない。`tutorial` の仕事。
- 使い方を長々と説明しない。使えば分かる。
