# グリル（知識抽出エンジン）

第二の脳のボトルネックは検索ではありません。ほぼ常に**捕獲**です。ニュアンスは本人の頭の中にあり、ファイルには届かない。`grill` はそこを直します。ある主題について本人を問い詰め、システムが理解したと言えるまで続け、その答えを**コンパイル**して正しいドメインに収めます（生の書き起こしを投げ込むのではなく）。

`distill`（世界から）、`log`（生の声）に対して、これは**自分自身から**の捕獲です。

## 始める前に（狙いを定める）

1. **対象を名指しする。** 何を抽出するのか（顧客、事業、人、決定、プロセス）。そして**どのドメイン**に入るのか。不明なら聞く。行き先のないグリルはただの雑談です。
2. **すでにある内容を読む。** ドメインの `index.md` と関連ファイルを読み込む。**システムが既に知っていることを聞かない**ため。質問は常に「今の知識の縁」から始める。
3. **枠組みを1行で述べる**：「<主題>について聞き出します。`domains/<domain>/` にコンパイルします。一問ずつ、全体像が見えるまで。もういいと思ったら言ってください。」
4. トピックマーカーを更新する（`printf '<domain>\nグリル: <主題>\n' > ".session/domain-$CLAUDE_CODE_SESSION_ID"`）。

## インタビュー（ここが本体）

- **一度に一問。** 5つまとめて聞かない。想起が崩れます。聞く、答えを受け取る、**そこで開いた糸を追う**、それから次へ。
- **網羅ごっこではなく、ニュアンスを追う。** 「なぜそれは失敗したのか」「二度とやらないことは何か」「実際に決めているのは誰か」。金脈は、本人しか持っていない具体・例外・意見の中にあります。
- **定期的に返して、鋭くする。** 聞いた内容を圧縮して読み上げ、「合っていますか、抜けは？」と聞く。**間違った要約に対してこそ、抜けが最速で出ます。**
- **素材を飲み込む。** 途中で契約書や書き起こしを貼られたら、吸収して**次の質問**に進む。内容を復唱しない。
- **作家としての自我を持つ。** 曖昧な答え、矛盾した答えは押し返す。弱い答えをそのまま真実として書き取らない。
- **やめどきを知る。** (a) 新しい質問が新しい情報を生まなくなった、(b) 行動できる程度に全体像が揃った、(c) ユーザーがもういいと言った。水増ししない。「ここまでで覆えたと思います」と述べて確認を取る。

## 取り込みゲート

すべての答えを Context / Connections のゲートに通します。**1年後も正しい知識だけが統合層に入ります。** 今週のもめごと、毎月変わる価格のような揮発物は索引に入れない。重要なら「どこを見れば分かるか」だけ残す。

## 終わったら（ダンプではなくコンパイル）

生のQ&Aのまま終わったグリルは失敗です。下から上へ書きます。

1. **ドメインの `index.md` にコンパイルする。** 抽出した真実を統合に畳み込む。追記ではなく更新。新しい対象なら、そのドメイン内に専用ファイルを作ってもよい。
2. **生の記録を残すかは任意。** 声や細部が保存に値するときだけ、一次情報として明記して残す。既定はコンパイルして書き起こしは捨てる。
3. **`closeout` 形式のエントリ**を `intentions-log.md` に追記する（主題、抽出したこと、変更ファイル、境界メモ、学び）。
4. **境界チェック**：主題が個人・商用の線をまたぐなら、書く前に宣言→タグ→確認。
5. ブランチでコミットし、同じセッションでマージする。

## 範囲

- **対象**：1つの主題を、1人（ユーザー）から、1つのドメインへ。
- **対象外**：チームの知識同期、外部ソースの学習（`distill`）、感情の記録（`log`）。
