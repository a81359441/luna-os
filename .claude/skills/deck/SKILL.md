# デッキ。中身を固めてから、デザインに入る

**間違ったメッセージに労力を注がずに**、きれいな資料を作ります。このスキルの原則は**中身を先にロックし、スライドは後で生成する**こと。**間違った論点の美しいデッキは、丸ごと無駄です。** だから「何を入れるか」を「どう見せるか」より先に詰めます。

デッキは**外向きの成果物**です。共有され得る瞬間から公開物として扱うこと。手順0の境界ゲートは省略不可です。

出力は**このリポジトリの外**、`../decks/<slug>/index.html` に置きます。ナレッジベースは非公開の真実、デッキは共有される層。混ぜないこと。

---

## 手順0: 境界ゲート（宣言 → タグ → 確認）

何よりも先に:

1. **宣言**: このデッキが何についてのもので、どのドメインの中身を使うか。
2. **タグ**: `#個人` / `#発信` / `#商用` / `#複合`。
3. **確認**: 何を入れてよいかをユーザーに確認する。譲れない線:
   - **コミュニティやメンバーの個人データは絶対に入れない。**
   - **取引先の名前、単価、収入、個人の財務の数字は絶対に入れない**（それらは別のプライベートリポジトリにあるはず）。
   - ナレッジベースから引くのは**共有してよい事実だけ**。自分が足元を見失わないよう、出典のドメインを自分に対して明示すること。

少しでも曖昧なら、進む前に聞く。

---

## 手順1: 中身を固める（HTMLを1行も生成する前に）

短い構造化された対話で中身を固めます。**まだスライドを作らないこと。**

- **聞き手**: 誰に向けたものか（1人 / チーム / 組織 / 出資者）。相手が既に知っていること、気にしていることは。
- **目的**: これを見せて得たい**1つの**結果。ひとつだけ「はい」をもらえるなら、それは何か。
- **中心のメッセージ**: 相手が持ち帰る1文。
- **柱**: そのメッセージを支える4〜8個の論点。8枚を超えると薄まるので、散らかっているなら押し返すこと。
- **語調と言語**: 日本語 / 英語 / 併記。温かく / 硬く / 軽く。聞き手に合わせる。
- **入れないもの**: 「将来の金額をちらつかせない」「具体的な数字は出さない」など、境界ゲートで挙がったもの。

そのうえで**スライドの構成案**（番号つきのタイトル一覧、各1行の説明）を出し、**明示的な承認をもらう**。ロックされるまで直す。

**構成がロックされてから、はじめてデザインの方向を提案する。** 既定の見た目に流さないこと。**その場に合わせて美意識を設計します**（聞き手・主題・気分）。**1〜3案**を具体的に出す:

- **気分 / コンセプト**: 一言で（例「焚き火のような親密さ」「投資家向けの清潔な北欧」「夜のネオン」「編集的なモノクロの静かな権威」）。
- **配色**: 背景 + 文字 + アクセント1〜2。実際の16進数で。
- **書体**: 合う Google Fonts の組み合わせ（見出し + 本文）。日本語なら明朝 / ゴシックの組み合わせも。
- **なぜ合うか**: 聞き手や文脈に結びつける1行。

選んでもらうか、混ぜてもらう。`template.html` に入っている配色は**参考例の1つであって既定ではありません。** ほとんどのデッキは自分の見た目を持つべきです。

**中身の構成とデザインの方向の両方**が確認されてから、手順2へ。

> なぜこのゲートがあるか: **構成とデザインを文章で直すのは安く、スタイル済みのデッキを作り直すのは高い**からです。メッセージと見た目を先にロックする。

---

## 手順2: デッキを生成する

1. このスキルのフォルダにある `template.html` を読む。これは**構造の骨**であって固定の見た目ではありません。クリック/矢印/ドットのナビ、段階的な表示、レスポンシブ配置、6種類のスライド原型が入っています。配色と書体は**サンプル**なので、確定したデザイン方向に差し替える。`<script>` とナビの枠（`.brand/.counter/.nav/.dots`）、構造のCSS（`.slide/.rise/.stage/.list/.stats/.paths`）はそのまま残し、**見た目は `:root` のトークンと Google Fonts の `<link>` で変える**。
2. `<section class="slide">` を、ロックした構成の中身に差し替える。原型は `template.html` の冒頭に説明があります: タイトル / 箇条書き+注 / リード文 / 数字の並び / カード・二択 / 締め。
3. 各 `<section>` に `data-i` を順番に振る。**総数はスクリプトが自動で数える**ので手で書かないこと。
4. `../decks/<slug>/index.html` に書く（主題から kebab-case のスラグ）。無ければディレクトリを作る。
5. 1枚目に `active` を付けて、読み込み時に1枚目が出るようにする（雛形は既にそうなっています）。
6. **スマホで成立することは必須要件です。** デッキはLINEやSNSからスマホで開かれます。雛形はこれらを持っているので、作り直すときも壊さないこと:
   - **スワイプで進む**（横のタッチ。縦はスライド内のスクロールのために空けておく）。
   - **ブラウザの枠の色を合わせる**: `<meta name="theme-color">` と `html{background}` の**両方**を背景のトークンと同じにする。片方だけだと、スマホの上下のバーだけ色がずれます。
   - **セーフエリア**: `viewport-fit=cover` と `env(safe-area-inset-*)` を、固定表示の要素すべてに。
   - **狭い画面で、文字の上に絶対配置の装飾を重ねない**。620px以下のメディアクエリで `position:static` に落とす。
   - **仕上げる前に幅390pxで確認すること。**

## 手順3: プレビューと微調整

ブラウザで開いてもらう（`open ../decks/<slug>/index.html`）。「4枚目を柔らかく」「5と6をまとめて」「タイトルを大きく」のような普通の言葉で直していく。編集はこちらでやること。根拠が残り、バージョン管理できます。

---

## 手順4: 公開（任意。頼まれたときだけ）

**公開する前に境界をもう一度確認すること。** 公開URL = 公開されている、推測可能、ということです。

```
npx --yes surge ../decks/<slug> <slug>.surge.sh
```

（Surge のサブドメインは世界で共通の名前空間です。埋まっていたら、もっと特徴的なスラグで取り直す。同じコマンドを再実行すると同じURLを即座に上書きします。）最後に `https://<slug>.surge.sh` を渡す。

**アクセス解析.** 雛形は静かな **GoatCounter** のスニペットを持っています（軽く、Cookieを使わない）。一度だけ goatcounter.com に登録して、解析の `<script>` の `GC_CODE` にサブドメインを入れれば有効になります。1つのダッシュボードで全部のデッキを見られます。`GC_CODE` が空のうちは何もしません。

## 締め

デッキの**道具・仕組み**の話 → `tasks/backlog.md` へ。**特定のドメインの目的のために作ったデッキ** → そのドメインの `intentions-log.md` に1行で十分です。**デッキのファイル自体が成果物であって、真実の置き場ではありません。**

落ち着いて、一度に1つ。**中身をロックしてから、デザイン。** 常に。
