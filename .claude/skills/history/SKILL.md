# 履歴

「最近なにをしていたか」「あれはどのセッションだったか」に答えます。

実務は **`bin/sessions`** がやります（決定的な処理。モデルのトークンは使いません）。このスキルは**読み上げと、その上の判断**だけです。

## 手順

1. **走らせる。** `bin/sessions` で直近12件、`--top N` でもっと、`--all` で見出しの取れない探り用セッションも含める。
2. **一覧はコードブロックでそのまま再現する。** スタートメニューと同じ扱い。等幅でないと列が揃いません。
3. **特定のものを探しているなら、目視で走査させない。** まずセッション台帳（`tasks/sessions.md`、またはシステム用ドメインの `sessions.md`）を grep し、次に最初の依頼文を grep して、該当行を名指しする。最初の依頼はたいてい良い見出しになり、台帳の行は**実際に何が出たか**を言います。
4. **1つを辿り直すなら:** `bin/sessions <番号>` が詳細と再開コマンドを出します。`claude --resume <id>` を**ユーザーに手渡す**こと。**自分で実行しない**（セッションを開くのは本人の行為です）。

## 何を読んでいるか

- **`~/.claude/projects/<slug>/*.jsonl`**: Claude Code 自身の記録。日付、ターン数、git ブランチ、そしてユーザーが最初に言った実のある一言。メニューの選択や相槌（「m」「ok」）は見出しとして飛ばします。
- **セッション台帳**: `closeout` が書いた結果の行。セッションidで突き合わせます。**記録は何を「訊かれた」かを知っていて、締めだけが何が「出た」かを知っている。**

## 境界

- **`h` は過去に向かう全体の年表**（全セッション、軽い）。**`resume` は絞り込んだ一覧**（`closeout` の「続ける」出口で途中保存した仕事。`next:` を持つ `[~]` の backlog 項目）。混ぜないこと。片方を訊かれてもう片方を出さないこと。
- **記録は端末ローカル。** `~/.claude` はリポジトリの中に無いので、**セッションidで開き直せるのはそれを作った端末だけ**です。黙って失敗させず、そう言うこと。台帳の行自体はどこででも読めます。
- **読み取り専用。** このスキルは何も書きません。セッションの記録を書くのは `closeout` です。結果を知っているのはそれだけだからです。
