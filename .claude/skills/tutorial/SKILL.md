# チュートリアル（はじめの一歩）

`tasks/onboarding.md` の、まだ印のない項目を**上から1つだけ**やる。終わったら `- [x]` にして保存し、次は何か1行で伝えて止まる。2つ続けてやるかは相手が決める。

相手はターミナルに慣れていない。日本語で、**1回に1画面ぶん**だけ指示し、「できました」を待ってから次へ。画面の文言が英語なら、日本語の意味を添える。

## なぜ Claude のコネクタではなく、自前のスクリプトなのか

Gmail とカレンダーは `bin/gmail` と `bin/gcal` で、Google の API に**直接**つなぐ。

- **どのAIでも使える。** Claude Code でも Codex でも Grok でも、同じスクリプトを呼ぶだけ。つなぎ先がAIの会社の設定画面に閉じない。
- **ブリーフに出せる。** 起動時のブリーフ（`bin/menu`）はスクリプトなので、カレンダーをファイル経由で読める。コネクタはAIの会話の中からしか使えない。
- **鍵が手元にある。** トークンは `.secrets/`（gitignore 対象）にあり、権限の段階（読むだけ／下書きまで、など）を自分で選べる。

代わりに、最初の準備（Google Cloud）が20分ほどかかる。これは1回だけ。

## Gmail をつなぐ（Google の準備も一緒に）

手順の正本は **`bin/gmail/README.md`**。読んで、その順に1画面ずつ案内する。ここには、案内のコツだけを書く。

1. **始める前に1行で伝える**：「Google の開発者向けの画面を使います。無料です。英語や見慣れない画面が出ますが、言うとおりに押せば大丈夫です。20分ほどです。」
2. **Google Cloud のプロジェクト作成 → Gmail API を有効に → 同意画面 → テストユーザーに自分のアドレス → デスクトップアプリのクライアント作成 → JSON をダウンロード。** README の順のまま。
   - プロジェクト名やアプリ名は、AIの名前でよい（例：`luna`）。
   - **テストユーザーの追加を飛ばさせない。** 飛ばすと最後の承認で必ず拒否される。
   - 同意画面は最後に**「アプリを公開」**まで進めてもらう。テストのままだと、7日ごとにつなぎ直しになる。
3. **ダウンロードした JSON を所定の場所へ。** 相手に Finder で動かさせない。ファイル名を聞いて、AIが移す：
   ```bash
   mkdir -p .secrets && mv ~/Downloads/client_secret_*.json .secrets/gmail-client.json
   ```
4. **承認**：`python3 bin/gmail/auth.py` を実行（既定は読むだけ）。ブラウザが開く。
   - 「このアプリは Google で確認されていません」は正常。**詳細 → （アプリ名）に移動** で進む、と先に伝えておく。
   - 下書きも作らせたい人には、後から `--compose` で権限を足せると伝える。ただし Google の仕組み上それは送信の許可も含む（README「つまずきやすいところ」）。必要になるまで足さない。
5. **確かめる**：`python3 bin/gmail/gmail.py whoami` でアカウントを確認し、`python3 bin/gmail/gmail.py search "newer_than:2d" --max 3` で直近の件名を見せる。「つながりました」。

## Google カレンダーをつなぐ

Gmail の準備が済んでいれば5分。手順の正本は **`bin/gcal/README.md`**。

1. Google Cloud の同じプロジェクトで **Google Calendar API を有効に**（検索バーに「Google Calendar API」→ 有効にする）。クライアントは Gmail と共用なので、新しく作るものは無い。
2. **どこまで触らせるか**を1つ選んでもらう。初めての人には `--narrow` を勧める：
   - `--narrow`（おすすめ）：AI専用のカレンダーだけに書き込み、あなたの予定は読むだけ。
   - 既定：あなたの予定も編集できる。
   - `--readonly`：読むだけ。
3. `python3 bin/gcal/auth.py --narrow`（選んだもの）→ ブラウザで承認。
4. `python3 bin/gcal/gcal.py init` で、AI専用のカレンダーを作る。スマホのカレンダーアプリに、別の色で出てくると伝える。
5. **確かめる**：`python3 bin/gcal/gcal.py agenda --days 7` で今週の予定を見せる。次に開いたときのブリーフの「今日」「今週」に予定が出る、と伝える。

## 締めてみる

項目が「締めて」なら、手順は要らない。「今日やったことが一段落したら『締めて』と言ってください。わたしが記録して、次のブリーフに反映します」と伝え、相手が実際に言ったときに `closeout` を走らせてから印を付ける。

## うまくいかないとき

- `invalid_grant`：トークン切れ。同意画面が「テスト」のまま。`auth.py` をもう一度（20秒）、恒久的には「アプリを公開」。
- `access_denied`／承認画面で拒否：テストユーザーに自分のアドレスが入っていない。
- `OAuthクライアントのファイルがありません`：手順3の移動ができていない。`ls ~/Downloads | grep client_secret` で探す。

## やらないこと

- 2つ以上を一度にやらない。
- 送信できる権限を勧めない。このAIはメールを送らない（送るのは人間）。
- `.secrets/` の中身を表示しない、コミットしない。
