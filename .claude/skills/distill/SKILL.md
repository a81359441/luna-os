# ディスティル（学習の取り込みエンジン）

外部ソースを、**自分の活動に橋渡しされた**恒久的な洞察に変え、`knowledge/domains/research/` に収めます。リポジトリに残すのは**本質**だけ。生の書き起こしは作業用ディレクトリに置き、コミットしません。これは分析であって、自分の事業についての事実ではありません。ラベルを分けること。

ドメインが無ければ最初の実行で `knowledge/domains/research/`（`notes/` 付き）を作ります。

## モード

- **チャンネル研究**（競合分析）：カタログを再生数で並べ、勝っている動画を研究する。既定は上位3本。
- **単体ソース**：動画1本、エピソード1本、記事1本を蒸留する。

**小さく試してから広げる。** まとめて処理する仕事（動画を何十本も、OCR、サブエージェントの並列）は、問いに答えられる最小の標本から始める。まず1件で通ることを確かめ、次に3〜5件。結果を見せ、全部に広げたときのコストを見積もり、**広げる前に聞く**。大量の処理はできるだけコードでやり、エージェントは多数より1つ。並列のファンアウトは、気づいたときには使用量を食い尽くしています。

## ステップ0 狙い

どの活動のための蒸留かを確認する（発信、事業、コンサル、投資…）。**行き先のない蒸留はただの雑学です。** 橋渡しが目的の全部です。

## ユーザー自身が見ていた場合のパス（重要）

標準の流れ：**リンク（＋本人の要点）→ こちらは黙って取得・評価 → まず本人の見解を聞く → 議論する → そのあとノートを書く。**

見解が一緒に来ていないなら、こちらの読みを見せる前に聞くこと。先に要約を見せると本人の記憶が汚染され、一次情報が失われます。**議論が収束するまでノートを書かない。** 本当の洞察は議論の中で鍛えられます。本人の反応は `## 自分の見解` として、ソースの主張ともこちらの分析とも分けて記録します。ここが、誰のAIでも出せる要約との差になる層です。

本人がまだ見ていないリンクを渡してきたときは、このパスを飛ばす（純粋な評価モード）。ただし、どちらのモードかは述べる。

## チャンネル研究の手順

1. **成績スキャン**：カタログを再生数で並べ、中央値からの外れ値を探す。
   ```bash
   yt-dlp -I 1:40 --print "%(view_count)s\t%(title)s\t%(id)s" "https://www.youtube.com/@HANDLE/videos" 2>/dev/null
   ```
2. **パッケージ解体**：勝っている動画のサムネイルを取得して**実際に見る**。タイトルを分解する（好奇心のギャップ、数字、顔、コントラスト、繰り返される視覚的サイン）。
   ```bash
   yt-dlp --skip-download --write-thumbnail --convert-thumbnails jpg -o "/tmp/research/%(id)s.%(ext)s" "https://youtu.be/ID"
   ```
3. **内容の解体**：勝ち動画の書き起こし、加えて**対照群として外した動画も数本**。勝ち負けの差にこそパターンが出ます。
   ```bash
   yt-dlp --skip-download --write-auto-sub --write-sub --sub-lang "ja.*,en.*" --sub-format vtt \
     --sleep-requests 2 -o "/tmp/research/%(id)s.%(ext)s" "https://youtu.be/ID"
   ```
   VTTをテキストに整える（タグと時刻を除去、ローリング字幕の重複を削る）。読むポイント：最初の10秒のフック、構成、離脱を防ぐ仕掛け、テンポ、締めの誘導。
4. **橋渡し**：パターンを、自分の活動で**実際に試せる仮説**に変換する。あわせて「自分にあって相手にない有利」を書く。
5. **ファイルにする**（下のテンプレート）。

**運用上の注意**：1回のコマンドで大量に取ると429（レート制限）になります。**1本ずつ**、`--sleep-requests 2` と数秒の間隔を空けて取ること。字幕APIが固く弾くようになったら、サムネイルはCDNから直接取れます（`curl -s -o t.jpg "https://i.ytimg.com/vi/<ID>/maxresdefault.jpg"`）。書き起こしは時間を置いて取り直す。

## ノートのテンプレート

`knowledge/domains/research/notes/YYYY-MM-DD-<slug>.md`

```markdown
---
title: <ソース名 短く>
date: YYYY-MM-DD
type: channel-study | source-distill
sources: ["<名前> <url>"]
ventures: [<橋渡し先>]
tags: [research]
status: 分析（事実ではない）
---
# <タイトル>

> **要旨** <一段落で刺さる形に>

## データ（チャンネル研究のとき）
## 勝ちパターン / 主要な洞察   番号を振り、他に移せる形で
## パッケージ解体   サムネとタイトル
## フック解体   最初の数行
## 引用できる言葉   2〜5個。話者名、忠実な言い回し、一行の文脈
## 自分の見解   本人の反応（一次情報。本人が見ていたときだけ）
## 橋渡し <活動名>へ   試せる具体的な仮説と、自分の有利
## 未解決 / 次
## 出典   URLと動画ID
```

**引用できる言葉は必須の節です。** 「なんかの動画で言ってた」は死んだ引用。話者名と文脈のついた一行は、会話でも提案でも使えます。後で必要になったとき、記憶からではなくこの節から出典つきで渡します。
