# エージェント層

このフォルダは「仕事をどう振り分け、実行し、レビューし、記録するか」を定義します。ナレッジベースの代わりではありません。**検証済みの知識は `knowledge/` にしかない**という原則は、エージェントを使っても変わりません。

## 構造

| 層 | 役割 | 権限の出どころ |
|---|---|---|
| **マスター** | ドメインを横断して調整し、仕事を振り分け、衝突を解決し、システムの整合性を守る | `CLAUDE.md`, `knowledge/index.md` |
| **サブエージェント** | 明確に限定された範囲の仕事を実行する | `.claude/agents/*.md`（実行可能）、`agents/registry.md`（索引） |
| **ドメイン** | 検証済みの知識と出典を持つ | `knowledge/domains/<domain>/` |
| **課題（Issue）** | 非自明な仕事の発注書 | `.github/ISSUE_TEMPLATE/agent-task.md` |

## 設計の原則

強いシステムは「たくさんの曖昧なエージェント」ではありません。**少数の、範囲が明確な役割**が、明示されたファイルと限定されたタスクとレビュー可能な出力で動くことです。

> ルール：スコープ、参照ファイル、期待する成果物、エスカレーション先を言えないなら、その仕事はまだエージェントに渡せる形になっていません。

サブエージェントは、ドメインの事実を発明しない、勝手に権限を広げない、チャットの記憶を検証済みの真実として扱わない。新しい知識が生まれたら、それは承認されるまで**提案**です。

## 使いどころの判断

**使う**：同じ種類の仕事が繰り返し発生していて、参照すべきファイル群がはっきりしていて、境界を守らせたいとき。長い資料を並列で読ませたいとき。

**使わない**：一度きりの仕事、マスターで足りる仕事、逐次的な多段の流れ（受け渡しが雑になりトークンも食う。フェーズに分けてファイルで引き継ぐ）。

エージェントを増やすのは、**実際にボトルネックが起きてから**で十分です。
